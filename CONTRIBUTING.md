# Contributing to DropDuo

DropDuo helps people who use a Mac and Android phone share files, text, and links through a focused native workflow. Start with the [product introduction](README.md), [product contract](docs/product.md), and [roadmap](docs/roadmap.md) to understand whom the app serves and what belongs in v1.

Read [AGENTS.md](AGENTS.md), [development setup](docs/development.md), and [Git standards](docs/git-workflow.md). Human and agent-assisted contributions follow the same review standard.

Open a focused issue with observed behavior, expected behavior, reproduction steps, platform versions, and acceptance criteria. Use Discussions for proposals. Never upload personal files, pairing QR codes, credentials, or private logs.

For normal contribution, branch `feature/<description>` or `fix/<description>` from develop. Keep the PR focused. Include what changed, why, impact, checks run, and device behaviors not tested. Link an issue if applicable. Protocol changes need compatibility tests and security review. At least one reviewer; no self-merge. No CLA is required; contributions are licensed under Apache-2.0.

You don't need to write code to help. Test a transfer in both directions on real devices, report confusing setup or file-saving steps, improve [user guides](docs/README.md), or review accessibility. Include the actual result and device versions; compilation alone isn't device evidence.

Keep public product copy grounded in implemented behavior. Cite primary sources when comparing competitors, distinguish shared benefits from exclusive features, and keep unverified speed/security/reliability claims out of the README. Update the [FAQ](docs/faq.md), [comparison](docs/comparison.md), and [validation evidence](docs/validation.md) when their facts change.
